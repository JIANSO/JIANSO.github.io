Q16회

root 원격 접속을 제한하기 위한 Solaris, AIX, HP-UX의 설정 파일을 쓰시오.

답과 해설 보기

답: ① /etc/default/login　② /etc/security/user　③ /etc/securetty

운영체제별 root 원격 접속 점검
  • Solaris — root 계정 원격 접속 가능 여부를 확인하기 위해 /etc/default/login 파일의 CONSOLE 옵션을 확인
  • Linux — /etc/pam.d/login 파일의 pam_securetty.so 모듈이 활성화되어 있는지 확인
  • AIX — /etc/security/user 파일의 rlogin 옵션이 false인지 확인
  • HP-UX — /etc/securetty 파일에 console이 존재하는지 확인

모범 답안과 해설 보기
모범 답안

① 인터넷에 직접 연결된 Windows 시스템에서 NetBIOS와 TCP/IP 바인딩이 활성화된 경우, 공격자가 네트워크 공유 자원을 악용할 위험이 존재

② 시작 → 실행 → ncpa.cpl → 로컬 영역 연결 → 속성 → TCP/IP → [일반] 탭에서 [고급] 클릭 → [WINS] 탭에서 "NetBIOS 사용 안 함" 또는 "NetBIOS over TCP/IP 사용 안 함" 선택

NetBIOS 바인딩 서비스 구동 점검 기준
  • 점검 내용 — NetBIOS 바인딩 서비스 구동 여부 점검
  • 점검 목적 — NetBIOS와 TCP/IP의 바인딩을 제거하여 파일 공유 서비스가 TCP/IP를 통해 동작하지 못하도록 하고, 인터넷을 통한 공유 자원 접근 시도를 차단하고자 함
  • 보안 위협 — 인터넷에 직접 연결된 Windows 시스템에서 NetBIOS와 TCP/IP 바인딩이 활성화된 경우, 공격자가 네트워크 공유 자원을 악용할 위험이 존재
  • 판단 기준
    • 양호 — TCP/IP와 NetBIOS 간의 바인딩이 제거된 경우
    • 취약 — TCP/IP와 NetBIOS 간의 바인딩이 제거되어 있지 않은 경우
  • 조치 방법 — 네트워크 제어판을 이용하여 TCP/IP와 NetBIOS 간의 바인딩(Binding) 제거

  1. 시작 → 실행 → ncpa.cpl네트워크 연결 창 열기
  2. 로컬 영역 연결 → 속성 → TCP/IP해당 연결의 TCP/IP 속성으로 이동
  3. [일반] 탭에서 [고급] 클릭
  4. [WINS] 탭"NetBIOS 사용 안 함" 또는 "NetBIOS over TCP/IP 사용 안 함" 선택

  • 판단 기준
    • 양호 — 주요 실행파일의 권한에 SUID와 SGID에 대한 설정이 부여되어 있지 않은 경우
    • 취약 — 주요 실행파일의 권한에 SUID와 SGID에 대한 설정이 부여되어 있는 경우
  • 조치 방법
    • 불필요한 SUID, SGID 파일을 제거
    • 애플리케이션에서 생성한 파일이나, 사용자가 임의로 생성한 파일 등 의심스럽거나 특이한 파일의 발견 시 SUID 설정의 제거가 필요

  • 불필요한 실행파일에 대한 SUID/SGID 설정 여부를 확인하고, SUID(4000) 또는 SGID(2000)가 설정된 파일을 찾음 # ls -alL [check_file] | awk '{ print $1}' | grep -i 's' # find / -user root -type f \( -perm -04000 -o -perm -02000 \) -xdev -exec ls -al {} \;
조치 명령어
  • <file_name>의 SUID/SGID 설정을 제거하고, 특정 그룹만 실행 가능하도록 제한할 경우 chgrp로 파일의 그룹을 특정 그룹으로 변경하고, chmod 4750으로 특정 그룹만 실행할 수 있도록 제한 # chmod -s <file_name> # chgrp <group_name> <setuid_file_name> # chmod 4750 <setuid_file_name>
Q524회

A 기업에서는 다양한 계열의 서버를 운영하고 있다. Solaris, Linux, AIX, HP-UX 서버에서 패스워드 최소 길이를 8자리 이상으로 강화하기 위한 설정 방법을 쓰시오.

모범 답안과 해설 보기
모범 답안

① Solaris — /etc/default/passwd 파일에서 PASSLENGTH=8로 설정

② Linux — /etc/security/pwquality.conf 파일에서 minlen=8로 설정

③ AIX — /etc/security/user 파일에서 minlen=8로 설정

④ HP-UX — /etc/default/security 파일에서 MIN_PASSWORD_LENGTH=8로 설정

운영체제별 패스워드 복잡성 설정
  • Solaris — /etc/default/passwd 파일을 내부 정책에 맞도록 설정
    • HISTORY=10 — 이전 10개의 패스워드는 사용 불가
    • MINDIFF=4 — 이전 패스워드와 4자 이상 달라야 함
    • MINALPHA=1 — 문자가 최소 1자 이상이어야 함
    • MINNONALPHA=1 — 숫자 또는 특수문자가 최소 1자 이상이어야 함
    • MINUPPER=1 — 대문자가 최소 1자 이상이어야 함
    • MINLOWER=1 — 소문자가 최소 1자 이상이어야 함
    • MAXREPEATS=0 — 연속된 문자의 사용이 불가능
    • MINSPECIAL=1 — 특수문자가 최소 1자 이상이어야 함
    • MINDIGIT=1 — 숫자가 최소 1자 이상이어야 함
    • NAMECHECK=YES — 아이디와 동일한 패스워드 사용 불가
    • PASSLENGTH=8 — 패스워드의 길이가 최소 8자리 이상이어야 함
  • Linux — /etc/security/pwquality.conf 파일을 내부 정책에 맞도록 설정
    • lcredit=-1 — 소문자가 최소 1자 이상 포함되어야 함
    • ucredit=-1 — 대문자가 최소 1자 이상 포함되어야 함
    • dcredit=-1 — 숫자가 최소 1자 이상 포함되어야 함
    • ocredit=-1 — 특수문자가 최소 1자 이상 포함되어야 함
    • minlen=8 — 패스워드의 길이가 최소 8자리 이상이어야 함
    • difok=N — 새 패스워드는 이전 패스워드와 최소 N개의 문자가 달라야 함 (N의 기본값은 10)
  • AIX — /etc/security/user 파일을 내부 정책에 맞도록 설정
    • dictionlist=/usr/share/dict/words — 패스워드에 /usr/share/dict/words에 등록된 단어가 포함되지 않도록 함
    • histexpire=26 — 26주 동안 이전 패스워드를 사용할 수 없음
    • histsize=10 — 이전 10개의 패스워드는 사용할 수 없음
    • maxrepeats=2 — 동일한 문자를 두 번 이상 사용할 수 없음
    • minalpha=2 — 알파벳을 최소 2개 이상 사용해야 함
    • minother=2 — 숫자, 특수문자를 최소 2개 이상 사용해야 함
    • mindiff=4 — 이전 패스워드와 4자 이상 달라야 함
    • minlen=8 — 패스워드의 길이가 최소 8자리 이상이어야 함
  • HP-UX — /etc/default/security 파일을 내부 정책에 맞도록 설정
    • MIN_PASSWORD_LENGTH=8 — 패스워드의 길이가 최소 8자리 이상이어야 함
    • PASSWORD_MIN_UPPER_CASE_CHARS=1 — 대문자가 최소 1자 이상 포함되어야 함
    • PASSWORD_MIN_LOWER_CASE_CHARS=1 — 소문자가 최소 1자 이상 포함되어야 함
    • PASSWORD_MIN_DIGIT_CHARS=1 — 숫자가 최소 1개 이상 포함되어야 함
    • PASSWORD_MIN_SPECIAL_CHARS=1 — 특수문자가 최소 1개 이상 포함되어야 함

모범 답안

(1) /etc/profile(.profile) 파일에서 TMOUT=600과 export TMOUT을 추가

(2) /etc/securetty

(3) ① 644　② 400

(4) find / -type f -perm -2

(5) umask 022

(1) 세션 타임아웃
  • vi 편집기로 /etc/profile 또는 /etc/.profile 파일을 연 후 TMOUT 값을 600으로 수정 # vi /etc/profile(.profile) TMOUT=600 export TMOUT
(2) Telnet 사용 금지
  • /etc/securetty 파일에서 pts/0 ~ pts/x 설정을 제거하여 Telnet 사용을 금지 # cat /etc/securetty #pts/x
(3) passwd · shadow 권한
  • /etc/passwd 파일의 소유자를 root로 변경하고, 권한을 644로 변경 # chown root /etc/passwd # chmod 644 /etc/passwd
  • /etc/shadow 파일의 소유자를 root로 변경하고, 권한은 400으로 변경 # chown root /etc/shadow # chmod 400 /etc/shadow
(4) world writable 파일 확인
  • world writable 파일의 존재 여부를 확인 # find / -type f -perm -2 -exec ls -l {} \;
(5) 기본 권한
  • umask 값을 022로 설정 # umask 022
