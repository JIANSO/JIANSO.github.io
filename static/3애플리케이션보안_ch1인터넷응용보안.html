Q12회

다음은 FTP와 관련된 설명이다. 괄호 (　) 안에 알맞은 용어를 쓰시오.

  • ( ① )은/는 기본적으로 UDP 포트 69번을 사용하여 통신하고, 보안 기능이 존재하지 않음에 따라 인증 등이 부재하기 때문에 취약하다.
  • ( ② ) 공격은 FTP 사용 시 사용자들이 서버에 자신을 식별시키지 않고서도 파일에 접근하는 방법을 제공하는 방식을 이용한 공격이다.
  • ( ③ ) 공격은 제어/데이터 채널을 다르게 사용하며, 데이터 채널 생성 시 추가적인 목적지 확인을 하지 않는 구조적 취약점을 이용한 공격이다.
답과 해설 보기

답: ① TFTP(Trivial File Transfer Protocol)　② 익명 FTP(Anonymous FTP)　③ FTP Bounce

  • TFTP
    • 인터넷 파일 전송 프로토콜
    • TFTP는 TCP/IP 프로토콜 스택을 기반으로 하며, 그 중 UDP(User Datagram Protocol)를 이용하여 작동하는 서비스
    • 보안 기능이 존재하지 않음에 따라 인증 등이 부재
  • 익명 FTP — FTP 사용 시 사용자들이 서버에 자신을 식별시키지 않고서도 파일에 접근하는 방법을 제공하는 방식
  • FTP Bounce 공격
    • FTP 서버가 데이터를 전송할 때 목적지가 어디인지 검사하지 않는 설계상의 문제점을 이용한 공격
    • 제어/데이터 채널을 다르게 사용하며, 데이터 채널 생성 시 추가적인 목적지 확인을 하지 않는 구조적 취약점을 이용한 공격
Q22회

다음 괄호 (　) 안에 알맞은 용어 및 파일명을 쓰시오.

( ① )은/는 리눅스 및 유닉스 기반 시스템에서 네트워크 서비스에 대한 접근 제어(Access Control)를 제공하는 보안 도구로 허용할 호스트를 명시하는 ( ② ) 파일 먼저 검사한 후에 해당하는 호스트가 없으면 거부할 호스트를 명시하는 ( ③ ) 파일을 확인하여 차단 규칙이 있는지 검사한다.
답과 해설 보기

답: ① TCP Wrapper　② hosts.allow　③ hosts.deny

  • TCP Wrapper는 리눅스 및 유닉스 기반 시스템에서 네트워크 서비스에 대한 접근 제어(Access Control)를 제공하는 보안 도구
  • hosts.allow 파일을 먼저 검사한 후에 hosts.allow에 해당 호스트가 없으면, hosts.deny를 확인하여 차단 규칙이 있는지 검사
  • /etc/hosts.allow — 허용할 호스트를 정의한 파일
  • /etc/hosts.deny — 거부할 호스트를 정의한 파일
Q310회

다음은 FTP에 대한 설명이다. 괄호 (　) 안에 알맞은 용어를 쓰시오.

FTP의 운영 모드는 ( ① ) 모드와 Passive 모드가 있다. ( ① ) 모드는 클라이언트에서 서버로의 명령과 서버 응답을 위한 ( ② )번 포트와 파일이 전송될 때 데이터를 주고받기 위한 ( ③ )번 포트를 사용한다. Passive 모드에서는 ( ④ )번 이상의 임의 포트를 사용한다.
답과 해설 보기

답: ① Active　② 21　③ 20　④ 1024

FTP 구성
  • 채널 (연결)
    • 제어 채널 (Control Channel) — 클라이언트에서 서버로의 명령과 서버 응답을 위한 연결, 서버는 TCP 21번 포트 사용
    • 데이터 채널 (Data Channel) — 파일이 전송될 때 데이터를 주고받는 연결, 서버는 TCP 20번 포트 사용, Passive Mode에서는 1024번 이상의 임의 포트 사용
  • 운영 모드
    • Active Mode — 서버에서 Data 채널 연결을 시도하는 모드 (기본으로 Active Mode가 실행)
    • Passive Mode — 클라이언트에서 Data 채널 연결을 시도하는 모드

FTP 채널
  • 제어 채널 (Control Channel) — 클라이언트에서 서버로의 명령과 서버 응답을 위한 연결, 서버는 TCP 21번 포트 사용
  • 데이터 채널 (Data Channel) — 파일이 전송될 때 데이터를 주고받는 연결, 서버는 TCP 20번 포트 사용, Passive Mode에서는 1024번 이상의 임의 포트 사용
Active Mode의 절차
  1. 명령 채널 접속 & DTP 포트 번호 전달클라이언트에서 서버의 21번 포트(PI)로 접속 후 클라이언트가 사용할 두 번째 포트(DTP)를 서버에 전송
  2. 서버 ACK서버는 ACK로 응답
  3. 데이터 채널 연결서버의 20번 포트는 클라이언트가 알려준 두 번째 포트로 접속 시도
  4. 클라이언트 ACK클라이언트가 ACK로 응답
FTP 운영 모드별 문제점
  • Active FTP 모드 (PC 차단 발생 가능)
    • 3단계에서 서버가 클라이언트로 접속을 시도하는 것이 문제
    • 클라이언트 PC에 방화벽이 설치되어 있다면 3단계 프로세스는 방화벽에 의해 차단되어 FTP 접속에 문제가 발생
  • Passive FTP 모드 (서버의 임의 포트 차단 발생 가능)
    • Data 포트로 Active 모드에서 사용했던 20번을 사용하지 않고 1024 이후의 임의 포트 사용하므로, 서버의 임의의 포트(1024~65535)를 서버 및 네트워크 방화벽에서 모두 열어야 한다는 문제가 발생 (대부분의 FTP 데몬에서 Passive 모드 접속 시 사용 포트 제한 설정으로 대부분 문제 해결할 수 있음)

모범 답안

① 메일 헤더에 표시된 발송 정보가 실제 메일을 발송한 서버와 일치하는지를 비교하여 발송자 정보의 위변조 여부를 파악할 수 있는 기술

② MAIL FROM에서 확인한 도메인을 바탕으로 수신 메일 서버는 DNS에 SPF 레코드(TXT 레코드)를 질의

③ 송신 메일 서버가 송신 DNS에 DKIM 공개키(TXT 레코드)를 등록하고, 수신 메일 서버는 이메일의 DKIM-Signature 헤더를 확인한 후, 발신 도메인의 DNS에서 DKIM 공개키를 조회

④ DMARC(Domain-based Message Authentication, Reporting and Conformance)

SPF 절차
  • SPF는 메일 헤더에 표시된 발송 정보가 실제 메일을 발송한 서버와 일치하는지를 비교하여 발송자 정보의 위변조 여부를 파악할 수 있는 기술
  1. 발신 메일서버 정보를 SPF 형식으로 등록도메인의 DNS에 SPF 레코드를 설정하여 허용된 발신 서버 목록을 지정
  2. 메일 발송발신 서버가 이메일을 수신 서버로 전송
  3. MAIL FROM 도메인을 확인수신 메일 서버는 MAIL FROM(Envelope From) 도메인을 확인
  4. DNS 질의MAIL FROM에서 확인한 도메인을 바탕으로 수신 메일 서버는 DNS에 SPF 레코드(TXT 레코드)를 질의
  5. SPF 레코드 수신수신 메일 서버가 DNS에서 해당 도메인의 SPF 레코드(TXT 레코드)를 수신
  6. 발신 IP가 SPF 레코드에 포함되는지 확인메일에 포함된 발신 메일 서버의 IP와 SPF 레코드(TXT 레코드)에 포함되어 있는지 IP 정보를 비교하여 발신 메일 서버의 IP가 SPF 레코드에 포함되어 있으면 통과, 그렇지 않으면 차단
DKIM 절차
  • DKIM은 메일의 송신자가 소유한 도메인 이름을 사용하여 메일을 서명하는 기능
  1. 공개키 정보를 DNS에 등록송신 메일 서버가 송신 DNS에 DKIM 공개키(TXT 레코드)를 등록
  2. 전자서명 후 메일 전송이메일 본문과 특정 헤더(From, Subject, Date 등)를 해싱(Hash) 처리하고, 생성된 해시 값을 개인키(Private Key)로 암호화하여 DKIM 서명을 생성하고, DKIM 서명을 DKIM-Signature 헤더로 추가
  3. 공개키 값 질의수신 메일 서버는 이메일의 DKIM-Signature 헤더를 확인한 후, 발신 도메인의 DNS에서 DKIM 공개키를 조회
  4. 전자서명 검증수신 메일 서버가 이메일 헤더 및 본문에서 해시 값을 추출하고 DKIM 서명을 공개키로 복호화한 값과 비교한 후에 같으면 수신, 다르면 차단
DMARC
  • DMARC는 도메인 소유자가 이메일 인증 실패 시 어떤 조치를 취할지 정의하고, 보고서를 받을 수 있도록 하는 프로토콜
  • DMARC는 SPF와 DKIM을 기반으로 이메일 인증 정책을 강화하는 프로토콜
