( ① )은/는 시스템의 특정 명령을 실행하기 위해 작성된 작은 크기의 프로그램으로, 일반적으로 기계어로 구성된다. ( ① )을/를 삽입할 때는 아무런 동작을 하지 않는 명령어인 NOP(No Operation)를 사용하여 공간을 확보하거나 실행 흐름을 유도하는데, 이 NOP 명령어의 16진수 값은 ( ② )이다.

답: ① 쉘 코드(Shell Code)　② 0x90　③ RET EIP ESP

Q523회

64비트 리눅스에서 다음 C언어 프로그램을 실행하려고 한다. printf 함수가 호출될 때, 'A', 'B', 'C' 각 파라미터가 저장되는 레지스터 명을 쓰시오.

01 #include <stdio.h> 02 int main() { 03 printf("%c %c %c", 'A', 'B', 'C'); 04 return 0; 05 }
답과 해설 보기

답: ① RSI(Extended Source Index)　② RDX(Extended Data Register)　③ RCX(Extended Counter Register)

  • 함수 호출 시 레지스터
    • RDI(Extended Destination Index) — 함수 호출 시 첫 번째 파라미터가 저장되는 레지스터
    • RSI(Extended Source Index) — 함수 호출 시 두 번째 파라미터가 저장되는 레지스터
    • RDX(Extended Data Register) — 함수 호출 시 세 번째 파라미터가 저장되는 레지스터
    • RCX(Extended Counter Register) — 함수 호출 시 네 번째 파라미터가 저장되는 레지스터
  • printf 함수에서 첫 번째 파라미터는 "%c %c %c"이므로 "%c %c %c"가 RDI에 저장되고, 두 번째 파라미터가 'A'이므로 'A'가 RSI에 저장되고, 세 번째 파라미터가 'B'이므로 'B'가 RDX에 저장되고, 네 번째 파라미터가 'C'이므로 'C'가 RCX에 저장됨
Q623회

리눅스 환경에서 컴파일 과정에 관한 설명이다. 괄호 (　)에 들어갈 용어를 쓰시오.

리눅스 환경에서 ( ① ) 방식은 프로그램을 실행할 때 외부 라이브러리를 런타임에 연결하는 방식이다. 이때 외부 라이브러리 함수를 사용할 수 있도록 주소를 연결 해주는 테이블인 ( ② )은/는 외부 함수의 실제 주소를 저장하는 테이블인 ( ③ )을/를 참고해서 외부 함수의 실제 주소를 가져온다.

답과 해설 보기

답: ① 동적 링킹(Dynamic Linking)　② PLT(Procedure Linkage Table)　③ GOT(Global Offset Table)

  • 동적 링킹은 프로그램을 실행할 때 외부 라이브러리를 런타임에 연결하는 방식
  • 동적 링킹은 컴파일하면 라이브러리가 프로그램 외부에 있기 때문에 함수의 주소를 알아오는 과정이 필요함
  • 동적 링킹의 PLT, GOT
    • PLT(Procedure Linkage Table) — 외부 라이브러리 함수를 사용할 수 있도록 주소를 연결 해주는 테이블 / 외부 함수 호출 시 PLT를 통해 함수를 호출함
    • GOT(Global Offset Table) — 외부 함수의 실제 주소를 저장하는 테이블 / PLT가 GOT 테이블을 참고해서 외부 함수의 실제 주소를 가져옴

  • DLP는 기업 내부의 민감한 데이터, 지적재산/사업 정보 및 고객 개인정보 등의 데이터 유출을 사전에 방지하기 위한 데이터 유출 방지 솔루션

  • 정당성의 원칙 — 증거는 적법한 절차를 거쳐서 수집해야 하며, 불법적인 수집은 증거 능력을 상실한다는 원칙
  • 재현의 원칙 — 획득한 증거는 동일한 조건과 상황에서 항상 같은 결과가 나와야 한다는 원칙 / 수행할 때마다 다른 결과가 나온다면 증거로서의 효력이 없음
  • 신속성의 원칙 — 증거 수집 과정은 신속히 진행되어야 한다는 원칙 / 메모리에만 남아 있는 휘발성 정보(예: 실행 중인 프로세스)는 대응이 지연되는 경우 적시에 확보하지 못할 가능성이 높아지므로 신속하게 대응해야 함
  • 연계 보관성의 원칙 — 증거는 수집(획득), 이송, 분석, 보관, 법정 제출의 일련의 과정이 명확하며, 추적할 수 있어야 한다는 원칙 / 디지털 증거의 발견 방법과 처리 방법을 비롯하여 증거와 관련된 모든 사항을 명확히 기술하고 보관 이송/과정에서 인수인계 과정에 대한 기록과 검증이 필요한 특성
  • 무결성의 원칙 — 수집된 정보는 각 단계를 거치는 과정에서 위변조되지 않음을 입증해야 한다는 원칙 / 수집한 증거가 위/변조되지 않고, 원본과 같음을 증명할 수 있어야 하고, 이를 보장하기 위해 해시값을 이용해 검증

해설
  • 단말 보안 솔루션 MDM(Mobile Device Management)
    • 스마트폰, 태블릿, 휴대용 컴퓨터 등의 디바이스를 관리하는 보안시스템
    • 보안 관리 및 도난 방지(기기의 루팅 탐지 및 차단), 앱 관리(원격 앱 설치 및 관리), 설정 관리(네트워크 설정), 자산 관리(운영 단말기 관리) 등
  • BYOD 보안 기술
    • 모바일 가상화(Hypervisors; Mobile Virtualization) — 한 개의 모바일 기기에 동일한 OS의 다중 인스턴스를 제공하는 소프트웨어 기반의 방법으로서 업무용과 개인용의 두 모드를 동시에 사용할 수 있도록 하는 기술
    • 가상데스크톱 인프라(VDI) — 서버에서 사용자가 필요한 가상 데스크톱 환경을 제공하는 방식
    • 클라우드 DaaS — 가상 데스크톱 환경을 클라우드 상에서 제공하는 서비스
    • 컨테이너화(Containerization) — 실행환경을 격리하는 기술로, 가상화된 샌드박스로 만들고 그 안에서만 기밀 정보 접근하거나 업무용 앱을 구동시키는 기술
    • 앱래핑(App Wrapping) — 단일 애플리케이션에 보안 정책을 실행할 수 있는 코드를 직접 삽입하여 앱을 수정하는 기술
