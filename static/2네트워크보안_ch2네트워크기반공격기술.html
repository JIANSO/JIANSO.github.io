Q12회28회

다음은 네트워크 기반 공격에 대한 설명이다. 괄호 (　) 안에 들어갈 알맞은 용어를 쓰시오.

( ① ) 공격은 공격자가 출발지 IP 주소를 피해자의 IP 주소로 위조한 후, 브로드캐스트 주소를 목적지로 하여 ( ③ ) 패킷을 전송함으로써, 해당 네트워크에 존재하는 다수의 호스트로부터 ICMP Echo Reply를 피해자에게 집중시키는 공격 기법이다. 이러한 공격에 대응하기 위해서는, 라우터에서 외부 네트워크로부터 유입되는 ( ② ) 트래픽을 차단하고, 각 호스트는 IP Broadcast Address로 전송된 ( ③ ) 패킷에 대해 응답하지 않도록 설정해야 한다.

답: ① Smurf　② Directed Broadcast　③ ICMP Echo Request

  • 호스트는 브로드캐스트 주소로 전송된 ICMP Echo Request 패킷에 대해 응답하지 않도록 시스템을 설정
  • 침입 차단 시스템(IPS)을 통해서 많은 수의 같은 ICMP Echo Reply 패킷이 전송되면 차단되도록 설정

Q39회

다음 괄호 (　) 안에 들어갈 용어를 쓰시오.

스머프 공격(Smurf Attack)은 공격 대상의 IP를 출발지 주소(Source IP)로 위조(Spoofing)한 후, 네트워크 내의 불특정 다수 시스템에 ICMP ( ① ) 패킷을 브로드캐스트로 전송한다. 이를 수신한 다수의 호스트는 위조된 출발지 주소(공격 대상 서버)로 ICMP ( ② ) 패킷을 동시다발적으로 응답하게 되어, 대상 서버의 가용성을 저하시키고 시스템 마비를 초래한다.
이러한 공격의 매개체로 악용되는 것을 방지하기 위해, 네트워크 경계에 위치한 라우터에서 다른 네트워크로부터 유입되는 ( ③ ) 패킷을 차단하도록 설정해야 한다. 또한 각 호스트는 브로드캐스트 주소로 전송된 ICMP ( ① ) 패킷에 대해 응답하지 않도록 커널 파라미터나 방화벽 설정을 변경해야 한다.
답과 해설 보기

답: ① Echo Request　② Echo Reply　③ Directed Broadcast

  • 공격자는 공격 대상 호스트의 IP 주소로 위장하여 ICMP Echo Request를 특정 IP 브로드캐스트(Broadcast) 주소로 보내게 됨
  • 공격 대상 IP 주소로 출발지 IP 주소를 설정하고 ICMP Echo Request 패킷을 브로드캐스트로 다수의 시스템에 전송하면, 공격 대상 서버는 ICMP Echo Reply 패킷들을 동시다발적으로 수신하여 시스템 성능에 문제를 일으키게 됨
  • 중간 매개자로 쓰이는 것을 막기 위해서 라우터에서 다른 네트워크로부터 자신의 네트워크로 들어오는 직접 브로드캐스트(Directed Broadcast) 패킷을 막도록 설정

답: Slowloris 공격(Slowloris Attack; Slow HTTP Header DoS Attack)

  • 정상적인 HTTP 메시지의 경우 헤더 정보가 '0D0A0D0A'로 종료되지만, Slowloris 공격 메시지는 '0D0A0D0A'가 없으므로 공격 대상이 되는 웹 서버는 헤더가 모두 도착하지 않은 것으로 간주하고 연결을 유지하고 서버의 자원을 잠식함

다음은 DoS 공격이다. 괄호 (　) 안에 들어갈 공격 기법을 쓰시오.

  • ( ① )은/는 출발지 IP와 목적지 IP를 같은 패킷 주소로 만들어 보냄으로써 수신자가 자기 자신에게 응답을 보내게 하여 시스템의 가용성을 침해하는 공격 기법이다.

  • ( ③ )은/는 TCP 프로토콜의 3-Way Handshake를 악용한 공격 기법으로 대표적인 자원 소진 공격이다.

답: ① 랜드 어택(Land Attack)　② 스머프 공격(Smurf Attack)　③ SYN Flooding 공격

  • 랜드 어택 — 출발지 IP와 목적지 IP를 같은 패킷 주소로 만들어 보냄으로써 수신자가 자기 자신에게 응답을 보내게 하여 시스템의 가용성을 침해하는 공격 기법
  • 스머프 공격 — 출발지 주소를 공격 대상의 IP로 설정하여 네트워크 전체에게 ICMP Echo 패킷을 직접 브로드캐스팅(Directed Broadcast)하여 목표 시스템을 마비시키는 공격 기법
  • SYN Flooding
    • TCP 프로토콜의 3-Way Handshake를 악용한 공격 기법으로 대표적인 자원 소진 공격
    • SYN Flag만 지속해서 전달하고 돌아오는 SYN/ACK 패킷에 대한 응답을 주지 않아서 피해 서버의 자원을 소모하게 만드는 공격 기법

Q918회

다음은 악성코드의 C&C(Command & Control) 통신 기법에 대한 설명이다. 괄호 (　) 안에 들어갈 올바른 용어를 쓰시오.

공격자는 보안 장비의 IP 차단 및 도메인 필터링 정책을 우회하기 위해, 고정된 주소를 사용하지 않고 시간(Time)이나 특정 값(Seed)을 기반으로 수많은 도메인 주소를 주기적으로 무작위 생성하는 기법을 사용한다. 공격자와 악성코드 감염 PC가 같은 (　　)을/를 사용하여 생성된 도메인 중 하나를 선택해서 통신하기 때문에 탐지가 어렵다.
답과 해설 보기

답: DGA(Domain Generation Algorithm)

  • DGA는 악성코드(Bot)가 C&C 서버와 통신하기 위해, 정해진 알고리즘을 통해 수많은 도메인 이름을 주기적으로 자동 생성하는 기법
  • DGA는 보안 장비(방화벽, IPS 등)의 IP/도메인 차단(Blacklist) 정책을 우회하기 위한 기법
DGA의 특징
  • IP/Domain 차단 회피 — 고정된 C&C 주소를 사용하지 않고 계속 변경하므로, 하나의 도메인을 차단해도 다음 생성된 도메인으로 접속
  • 대량의 도메인 생성 — 하루에 수백 개에서 수만 개의 도메인을 생성하지만, 실제로는 그중 1~2개만 등록하여 사용함
  • 시간 의존성 (Time-based) — 날짜, 시간 등을 시드(Seed)값으로 사용하여 매일 다른 도메인을 생성

[보기]　XSS, CSRF, SQL Injection, HTTP Request Smuggling

답: HTTP Request Smuggling

  • HTTP 요청 스머글링은 서버 간 요청 처리 방식의 차이를 악용하여, 악의적인 요청을 정상 요청 속에 숨겨 전송하는 웹 공격 기법
  • 주로 프론트엔드 서버와 백엔드 서버 간의 HTTP 요청 파싱 방식이 다를 때 발생
HTTP 요청 스머글링 유형
  • CL.TE (Content-Length to Transfer-Encoding) — 프론트엔드 서버가 Content-Length를 기준으로 요청을 해석하고, 백엔드 서버가 Transfer-Encoding: chunked를 기준으로 해석하는 경우 발생
  • TE.CL (Transfer-Encoding to Content-Length) — 프론트엔드 서버는 Transfer-Encoding: chunked 헤더를 우선적으로 처리하고, 백엔드 서버는 Content-Length 헤더를 우선적으로 처리하여 발생
  • TE.TE (Transfer-Encoding to Transfer-Encoding) — HTTP 요청 헤더에 Transfer-Encoding: chunked 헤더가 중복되어 사용될 때 발생

HTTP 헤더 구조
  • Cache-Control
    • 웹 서버의 부하를 감소시키기 위해 사용하는 캐싱 서버를 제어하는 필드
    • 캐시 값을 지정하지 않았을 경우 특정 웹 리소스의 모든 캐싱이 되지 않게 하며, 악용되어 사용될 경우 서버에 부하를 발생하는 공격으로도 사용될 수 있음
    • max-age — 캐시된 데이터의 유효시간을 설정하는 옵션 (max-age=30이면 30초 동안 유효함)
    • no-store — 데이터의 캐시를 허용하지 않는 옵션
    • no-cache — 데이터 캐시는 허용하지만, 사용하기 전에 반드시 서버에 재검증을 요청하여 데이터의 유효성을 확인해야 하는 옵션 (max-age=0과 같음)
    • must-revalidate — 캐시된 데이터의 유효시간이 만료되면 반드시 서버에 새로운 응답을 사용하는 옵션
  • Connection — 해당 요청이 끝난 후에 클라이언트와 서버가 계속해서 네트워크 연결을 유지할 것인지 끊을 것인지에 대해 지시하는 필드
  • Content-Type — 해당 요청이 보내는 본문(Body)의 데이터 타입을 나타내는 필드
  • Content-Length
    • 본문(Body)의 길이를 나타내는 필드 (바이트 단위)
    • POST 방식을 사용할 때 동봉되는 데이터의 크기
  • Host
    • 요청을 받는 서버의 URL을 나타내는 필드
    • 요청 대상 서버의 도메인명
  • User-Agent
    • 요청을 보내는 클라이언트에 대한 정보를 나타내는 필드
    • 클라이언트의 웹 브라우저 및 OS 정보
  • Referer
    • 이전 페이지의 URL 주소를 알려주는 필드
    • 요청을 보낸 페이지의 절대 혹은 부분 주소를 포함
  • Cache-Control 필드에 no-cache, no-store, must-revalidate를 포함한 메시지를 계속 보내면 서버에 부하가 많이 가게 되는데, 이러한 공격을 CC(Cache-Control) 공격이라고 함

일반적으로 스위치 장치는 MAC 주소 테이블이 가득 차면 모든 네트워크 세그먼트 트래픽을 브로드캐스팅한다. 공격자는 이러한 특성을 악용하여 위조된 MAC 주소를 지속적으로 네트워크에 흘려보냄으로써, 스위칭 허브의 주소 테이블을 오버플로우시킨다. 이로 인해 스위치가 더미 허브처럼 동작하게 되어 해당 네트워크 세그먼트의 데이터를 스니핑할 수 있다.
답과 해설 보기

답: Switch Jamming 공격

  • Switch Jamming은 스위치가 받은 데이터를 특정 목적지에 전송하기 위한 MAC 주소 테이블에 대해 버퍼 오버플로우 공격을 수행하여 스위치가 더미 허브처럼 동작하게 만드는 공격
공격 순서
  1. 공격자가 스위치에 랜덤한 형태로 생성한 MAC을 대량으로 전송하여 스위치의 MAC 주소 테이블의 저장 용량을 초과시킴(오버플로우)
  2. 스위치의 원래 기능을 잃고 더미 허브(Dummy Hub)처럼 동작
  3. 스위치의 주소 테이블이 모두 차면 모든 네트워크에 패킷을 브로드캐스팅
  4. 브로드캐스팅 된 패킷 정보를 스니핑

TCP 통신 중에 RST 패킷(Reset)을 보내 일시적으로 TCP 세션을 끊고 시퀀스 넘버를 새로 생성하여, 세션을 탈취하고 인증을 회피하는 공격은 무엇인지 쓰시오.

답과 해설 보기

답: TCP 세션 하이재킹

  • TCP 통신에서 세션을 유지하는 데 사용하는 패킷의 순서(시퀀스 번호, ACK 번호)를 조작하여 공격자가 통신 세션을 가로채는 공격 기법
공격 순서
  1. 세션의 시퀀스 번호 획득
    • 공격자는 ARP Spoofing을 통해 패킷이 공격자를 지나가게 함으로써 세션 정보를 확인(스니핑)하고 클라이언트의 시퀀스 넘버를 획득
  2. RST 패킷 전송
    • 공격자는 정상적인 클라이언트의 IP 주소로 위장하고 RST 패킷을 보내 클라이언트와 서버 쪽 연결을 단절시킴
    • 서버는 잠시 Closed 상태가 되나 클라이언트는 그대로 Established 상태로 유지
  3. 서버와 신규 세션 연결
    • 공격자는 새로운 시퀀스 넘버를 생성하고, 서버와 TCP 3-Way Handshaking을 수행
  4. 공격자-서버 시퀀스 번호 사용
    • 서버는 신규 시퀀스 번호를 수신하고, 서버의 시퀀스 번호를 재생성하여 공격자에게 전달
  5. 중간자 세션 생성
    • 클라이언트 - 공격자 - 서버의 서로 간의 세션 Established를 유지하여 2개의 다른 세션 관리
  6. 통신 Relay 처리
    • 공격자가 TCP 연결의 중간자로 개입해 두 개의 시퀀스 번호를 사용해 통신을 중계
    • 기존 연결을 가로채 패킷을 서버에 전달하고, 서버의 응답(ACK)이 공격자와 클라이언트 모두에 전달됨
    • 클라이언트는 보낸 적 없는 데이터에 대한 ACK를 받고 이를 교정하려 다시 ACK를 보냄
    • 서버도 다시 ACK를 보내면서 양측이 반복적으로 ACK를 주고받아 ACK 스톰 발생
  7. 클라이언트 세션 종료
    • RST 또는 FIN 플래그를 가진 패킷을 클라이언트에게 보내 피해자의 세션을 종료
  8. 세션 조작
    • 세션이 가로채진 상태에서 공격자가 자신의 명령어 또는 요청을 서버에 전송하여 피해자의 권한으로 동작하게 만듦

네트워크 관리자(192.168.1.1)는 동료 직원 PC(192.168.1.75)와 통신을 하려고 하는데 연결이 간헐적으로 끊겨 ARP 캐시 테이블을 점검하였다. 이때 네트워크 관리자의 ARP 테이블을 확인한 결과는 다음과 같을 때 질문에 답하시오.

Internet AddressPhysical AddressType
192.168.1.6522-33-44-55-66-77dynamic
192.168.1.111-22-33-44-55-66dynamic
192.168.1.7522-33-44-55-66-77dynamic
192.168.1.8534-56-78-90-AB-CDdynamic
  • ① 어떤 공격인지 쓰시오.
  • ② 해당 공격이라고 추정하는 이유를 서술하시오.
  • ③ 공격자로 추정되는 시스템의 IP 주소를 쓰시오.
  • ④ 해당 공격을 방지하기 위한 대응 방안을 서술하시오.
모범 답안과 해설 보기
모범 답안

① ARP 스푸핑 (ARP Spoofing)

② ARP 테이블을 확인한 결과, 공격자(192.168.1.65)와 일반 호스트(192.168.1.75)의 MAC 주소가 22-33-44-55-66-77로 동일한데, 이는 공격자가 자신을 192.168.1.75 호스트인 것처럼 MAC 주소를 위조하여 등록시킨 것이기 때문

③ 192.168.1.65

④ ARP 테이블을 정적(Static)으로 설정하여 변경되지 않도록 함

  • ARP 스푸핑은 공격자가 특정 호스트의 MAC 주소를 자신의 MAC 주소로 위조한 ARP Reply를 만들어 희생자에게 지속해서 전송하여 희생자의 ARP 캐시 테이블에 특정 호스트의 MAC 정보를 공격자의 MAC 정보로 변경하는 기법
  • ARP 테이블을 확인한 결과, 공격자(192.168.1.65)와 동료 직원 PC(192.168.1.75)의 MAC 주소가 22-33-44-55-66-77로 동일함. 이는 공격자가 자신을 192.168.1.75 호스트인 것처럼 MAC 주소를 위조하여 등록시킨 것이므로 ARP 스푸핑 공격임
  • ARP 스푸핑에 대한 보안 대책으로 동일 네트워크 내의 시스템들에 대한 ARP 캐시 테이블을 관리자가 직접 정적(Static)으로 설정함으로써 대응할 수 있음
  • 정적 ARP 테이블을 사용하는 시스템은 ARP Reply 메시지를 무시하므로 악의적인 전송 메시지를 방어할 수 있음 arp -s [IP 주소] [MAC 주소]
Q219회26회

시스템 로그 점검 중 다음과 같은 로그가 발견되었다. 로그를 참고하여 질문에 답하시오.

# cat /var/log/messages | grep 'promiscuous mode' Jan 01 12:00:00 soojebi kernel: device eth0 entered promiscuous mode
  • ① 로그에 나타난 promiscuous mode의 의미를 서술하시오.
  • ② promiscuous mode가 설정된 환경에서 발생할 수 있는 대표적인 공격 기법을 서술하시오.
  • ③ 위와 같은 공격을 탐지하거나 대응하기 위한 보안 방안을 두 가지 이상 서술하시오.
모범 답안과 해설 보기
모범 답안

① 네트워크 인터페이스 카드(NIC)가 일반적으로 수신하지 않는 다른 호스트의 데이터 패킷을 수신할 수 있도록 설정된 모드

② 네트워크상에 전송되는 모든 트래픽을 수신할 수 있는 Promiscuous Mode 설정을 통해 데이터를 도청할 수 있는 스니핑 공격이 발생할 수 있다.

③ 데이터를 암호화하여 스니핑을 통해 가로채더라도 해독할 수 없도록 보호, 스위치의 주소 테이블을 static하게 설정하여 MAC 주소를 특정 포트에 고정하여 공격을 방지

  • Promiscuous Mode는 네트워크 인터페이스 카드(NIC)가 일반적으로 수신하지 않는 다른 호스트의 데이터 패킷을 수신할 수 있도록 하는 모드
  • 이더넷 인터페이스는 자신의 MAC 주소를 갖지 않는 트래픽을 무시하는 특성이 있으나, 스니핑 공격을 통해 필터링을 무시하고 모든 트래픽을 볼 수 있는 Promiscuous Mode를 설정하여 트래픽을 도청함
  • /var/log/messages 로그 파일은 로그 발생 시간, 호스트 이름, 로그 출처(커널, 시스템 서비스 등), 메시지 내용이 출력됨
스니핑 공격 대응 방안
  • 데이터 암호화
    • 데이터를 암호화하여 스니핑을 통해 가로채더라도 해독할 수 없도록 보호
    • 보안 프로토콜 및 VPN을 통한 데이터 보호
  • 안전한 네트워크 구성 설정
    • 정적(Static) ARP 테이블 설정을 통해 ARP 스푸핑을 통한 스니핑 방지
    • VLAN 구성을 통해 공격자가 같은 VLAN이 아니면 트래픽을 엿볼 수 없도록 구성
    • 스위치 포트에 지정된 MAC 주소만 접속을 허용하고, 미인가 장비 접속 시 자동 차단되도록 보안 설정
  • 스니퍼 탐지 도구 사용
    • NMAP 등의 도구를 이용해 네트워크에서 Promiscuous 모드로 동작하는 호스트를 탐지하여 스니핑 시도를 필터링 및 차단
    • 네트워크상의 ARP 트래픽을 감시하여 MAC 주소와 IP 주소의 매핑이 변경될 때 관리자에게 알려주는 ARP Watch 도구 활용
Q325회

네트워크 스니핑 탐지 기법 중 하나인 ping 명령을 이용한 탐지 방법의 원리를 서술하시오.

모범 답안과 해설 보기
모범 답안

의심되는 호스트에 대해 네트워크에 존재하지 않는 MAC 주소로 위장하여 Ping을 보내면 스니퍼를 탐지할 수 있음

스니핑 탐지 방법
  • ping 활용
    • 의심되는 호스트에 대해 네트워크에 존재하지 않는 MAC 주소로 위장하여 Ping을 보내면 스니퍼를 탐지할 수 있음
    • 스니핑을 하지 않는 호스트라면 Ping Request를 볼 수 없음
  • ARP 활용 — 위조된 ARP Request를 전송했을 때 ARP Response가 도착하면 Promiscuous Mode로 설정된 것으로 탐지할 수 있음
  • 프로그램 활용 — 스니핑 모니터링 프로그램인 Sentinel을 이용하여 스니퍼를 탐지

네트워크 관리자는 인터넷 접속 속도가 현저히 저하되는 현상을 확인한 후, 원인을 분석하기 위해 PC의 ARP 캐시 테이블을 조회하였다. 조회 결과는 다음과 같다. 해당 정보를 참고하여 다음 질문에 답하시오. (단, 해당 네트워크의 정상적인 게이트웨이 IP 주소는 192.168.100.1이다.)

Internet AddressPhysical AddressType
192.168.100.111-22-33-44-55-66dynamic
192.168.100.511-22-33-44-55-66dynamic
192.168.100.2000-11-22-33-44-55dynamic
192.168.100.21AA-BB-CC-DD-EE-FFdynamic
192.168.100.2200-11-22-AA-BB-CCdynamic
  • ① 현재 PC에서 ARP 캐시 테이블을 조회하기 위해 사용한 명령어를 쓰시오.
  • ② 위와 같은 ARP 캐시 테이블 상태를 통해 추정할 수 있는 공격 기법의 명칭을 쓰시오.
  • ③ 해당 공격으로 판단한 근거를 서술하시오.
  • ④ 실제 게이트웨이(192.168.100.1)의 MAC 주소가 22-33-44-55-66-77인 경우, 해당 공격에 대응하기 위해 관리자가 입력해야 할 명령어를 쓰시오.
모범 답안과 해설 보기
모범 답안

① arp -a

② ARP 리다이렉트(ARP Redirect)

③ 게이트웨이 IP 주소(192.168.100.1)의 MAC 주소가 11-22-33-44-55-66으로 변경

④ arp -s 192.168.100.1 22-33-44-55-66-77

  • ARP 캐시 테이블을 조회할 때 arp -a를 이용하여 조회 arp -a
  • ARP 리다이렉트 공격은 공격자가 라우터의 MAC 주소로 변경하여 ARP Reply 패킷을 대상 시스템에 브로드캐스트하는 공격
  • ARP 스푸핑에 대한 보안 대책으로 동일 네트워크 내의 시스템들에 대한 ARP 캐시 테이블을 관리자가 직접 정적(Static)으로 설정하면, 정적 ARP 테이블을 사용하는 시스템은 ARP Reply 메시지를 무시하므로 악의적인 전송 메시지를 방어할 수 있음 arp -s [IP 주소] [MAC 주소]
