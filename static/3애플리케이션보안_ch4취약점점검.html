Q523회

SQL Injection 취약점을 대응하는 방법에 대한 설명이다. 괄호 (　) 안에 들어갈 용어를 쓰시오.

[공격 대상 SQL 구문]
string query = "select * from member a where gubun = '" + a.gubun "'"
[대응 방법]
외부 입력값을 검증하지 않고 SQL문을 생성할 때 그대로 사용할 경우 보안 문제가 발생할 수 있다. 예를 들어, gubun 값으로 '' or 'a' = 'a'를 입력하면 쿼리가 항상 참이 되어 member 테이블의 모든 데이터가 조회될 수 있다. 이러한 SQL 인젝션 공격을 방지하려면, (　) 객체를 사용하여 SQL 문을 상수 문자열로 정의하고, setString과 같은 메서드로 파라미터를 바인딩해야 한다. 이를 통해 외부 입력이 SQL문의 구조를 변경하지 못하도록 차단할 수 있다.
답과 해설 보기

답: preparedStatement

  • Prepared Statement는 최초에 쿼리를 분석해 최적화 수행 후 메모리에 저장해두고, 다음 요청부터는 저장된 결과를 재사용하여 쿼리를 수행하는 방식
  • 사용자가 입력한 값이 SQL 명령의 일부가 아닌 매개 변수로 처리되기 때문에 SQL 인젝션 공격을 막을 수 있음
PreparedStatement 객체 사용 예
try { String tableName = props.getProperty("jdbc.tableName"); String name = props.getProperty("jdbc.name"); String query = "SELECT * FROM ? WHERE Name = ?"; stmt = con.preparedStatement(query); stmt.setString(1, tableName); stmt.setString(2, name); rs = stmt.executeQuery(); } catch (SQLException sqle) { } finally { }

Q728회

자바 스크립트를 통해서 쿠키를 접근하지 못하도록 막는 옵션으로, 쿠키를 통한 SessionID 노출을 막는 웹 서버 설정값은 무엇인지 [보기]에서 골라서 쓰시오.

[보기]　Secure, HttpOnly, Expires, Indexes, FollowSymLinks, FilesMatch
답과 해설 보기

답: HttpOnly

  • HttpOnly 설정은 자바스크립트 등의 스크립트를 통해 해당 쿠키에 접근하는 것을 차단하는 설정으로, 세션 ID 및 쿠키 탈취 등 크로스사이트스크립트(XSS) 공격에 대응할 수 있음
쿠키 보안 옵션
  • Secure
    • 쿠키가 HTTPS(SSL/TLS) 연결을 통해서만 전송되도록 제한하는 옵션
    • HTTP를 통한 쿠키 전송을 차단하여 중간자 공격(Man-in-the-Middle; MITM)이나 패킷 스니핑을 방지할 수 있음
  • HttpOnly
    • JavaScript를 통해 쿠키에 접근할 수 없게 되어, 악성 스크립트를 통해 쿠키 값에 접근하는 것을 막아줌
    • 자바스크립트(document.cookie)를 이용한 쿠키 접근을 차단하는 옵션
    • XSS(Cross-Site Scripting) 공격으로부터 보호하여 공격자가 악성 스크립트를 삽입해 쿠키를 탈취하는 것을 방지
  • Expires
    • 쿠키의 만료 시간을 설정하는 옵션
    • 짧은 만료 시간을 설정하여 공격자가 탈취하더라도 빠르게 무효화되도록 함
  • 애플리케이션 코드 설정 — Java에서는 cookie.setHttpOnly(true)를 통해서 사용

    • 실제 파일의 헤더를 변조하여 MIME 타입을 속이면 서버에서 $_FILES['userfile']['type'] 값이 변조될 수 있음
    • 개발자 도구를 사용하여 실제 파일의 헤더를 변경하면 Content Type을 허용된 MIME 타입으로 변경할 수 있음
  • 파일 확장자 변조 — 허용된 확장자로 파일명을 변경하여 우회하는 방식 예: webshell.php 파일을 webshell.jpg로 변경
  • 파일 이름에 Null 바이트 삽입 — Null 바이트(\0 또는 %00, ASCII 코드 0x00)를 이용하여 확장자 검사를 우회하는 공격 기법 예: webshell.php 파일을 webshell.php%00.jpg로 → jpg 파일이라 업로드는 허용되고, PHP가 문자열을 처리할 때는 webshell.php로 인식
공격이 성공하기 위한 조건
  • 서버 측 검증 미흡
    • 파일 확장자 검사가 없거나 불완전할 경우
    • $_FILES['userfile']['type']만 검증하고 실제 MIME 타입 검증을 수행하지 않는 경우
  • 파일 저장 위치 및 실행 가능 여부 — 업로드된 파일이 웹 서버의 실행 가능한 디렉터리에 저장되는 경우
  • 클라이언트 측 검사만 의존 — 클라이언트에서 조작할 수 있는 Content-Type 값만 검사하는 경우
  • 서버 설정 미흡
    • Apache 설정 파일인 httpd.conf에 해당 디렉터리에 대한 문서 타입을 컨트롤하기 위해 Directory 섹션의 AllowOverride 지시자에서 FileInfo 또는 All 추가하지 않음
    • .htaccess는 Apache 서버에서 특정 디렉터리의 설정을 제어하는 구성 파일로 FileMatch 지시자, AddType 지시자를 이용하지 않음

데이터베이스 관리가 미흡한 경우, 비인가자가 DB에 접근하여 정보 유출, 훼손, 파괴 등 악의적인 행위가 이루어질 수 있다. 다음 질문에 답하시오.

  • (1) DBA가 일반 사용자 또는 원격 사용자에게 부여하면 안 되는 권한 3가지를 쓰시오.

모범 답안과 해설 보기
모범 답안

(1) ① 데이터베이스 객체를 생성하는 권한　② 데이터베이스 객체를 변경하는 권한　③ 데이터베이스 객체를 삭제하는 권한

(2) ① 기본 계정의 패스워드, 정책 등을 변경하여 사용　② 데이터베이스의 불필요 계정을 제거하거나, 잠금 설정 후 사용　③ 패스워드의 사용기간 및 복잡도를 기관 정책에 맞도록 설정　④ 데이터베이스 관리자 권한을 꼭 필요한 계정 및 그룹에 허용 등

DBA 이외에 부여하면 안 되는 권한
  • DBA가 가지는 시스템 권한 중 CREATE, ALTER, DROP은 매우 강력하기 때문에 DBA 이외에는 부여하면 안 됨
  • CREATE — 데이터베이스 객체를 생성하는 명령어예: CREATE USER, CREATE ANY TABLE
  • ALTER — 데이터베이스 객체를 변경하는 명령어예: ALTER DATABASE, ALTER SYSTEM
  • DROP — 데이터베이스 객체를 삭제하는 명령어예: DROP USER, DROP ANY TABLE

    • 데이터베이스의 불필요 계정을 제거하거나, 잠금 설정 후 사용
    • 패스워드의 사용기간 및 복잡도를 기관 정책에 맞도록 설정
    • 데이터베이스 관리자 권한을 꼭 필요한 계정 및 그룹에 허용
  • 접근 관리
    • 원격에서 DB 서버로의 접속 제한
    • DBA 이외의 인가되지 않은 사용자 시스템 테이블에 접근할 수 없도록 설정
    • 리스너의 패스워드를 설정하여 사용
  • 옵션 관리
    • 응용프로그램 또는 DBA 계정의 Role이 Public으로 설정되지 않도록 설정
    • OS_ROLES, REMOTE_OS_AUTHENTICATION, REMOTE_OS_ROLES를 FALSE로 설정

다음의 Oracle Database의 감사 정책 설정을 보고 질문에 답하시오.

SQL> show parameter audit NAME TYPE VALUE -------------------- --------- ------------------------------------ audit_file_dest string /oracle/app/oracle/admin/ORCL11/adump audit_sys_operations boolean FALSE audit_syslog_level string audit_trail string NONE
  • ① 오라클 감사 기능에 대한 활성화 여부를 지정하는 매개변수는 무엇인지 쓰시오.
  • ② ①의 값을 바꿔 SYS.AUD$ 테이블로 경로 변경 설정하시오.
  • ③ 감사추적은 내부에 저장하는 것보다 외부에 저장하는 것을 권장한다. 보안관점에서 해당 이유를 서술하시오.
모범 답안과 해설 보기
모범 답안

① AUDIT_TRAIL

② ALTER SYSTEM SET AUDIT_TRAIL = DB SCOPE=SPFILE;

③ 감사 기록을 외부 시스템에 실시간으로 전송하여 저장하여 기록 변조를 불가능하게 하여 무결성 보장

Oracle 감사 매개변수
  • AUDIT_FILE_DEST — 감사 파일을 저장할 디렉터리 경로를 지정하는 매개변수예: /oracle/app/oracle/admin/ORCL11/adump
  • AUDIT_SYS_OPERATIONS — SYSDBA 등 최고 권한 세션의 활동을 감사할지 여부를 설정하는 매개변수
    • FALSE — 최고 권한 활동에 대한 감사를 비활성(기본값)
    • TRUE — 최고 권한 활동에 대한 감사를 활성
  • AUDIT_SYSLOG_LEVEL — 감사 메시지를 Syslog로 보낼 때의 facility/priority 수준을 지정하는 매개변수예: LOCAL1:CRITICAL, USER:NOTICE 등
  • AUDIT_TRAIL — 감사 기능에 대한 활성화 여부를 지정하는 매개변수
    • NONE — 감사를 비활성함
    • DB — 감사를 활성화함(감사 결과는 SYS.AUD$에 저장)
    • OS — OS에서 허용하는 경우 활성화함
SQL> alter system set audit_trail=DB scope=spfile;

  • 데이터베이스 장애 시 감사 연속성 확보 — 데이터베이스 서버의 가용성과 관계없이 독립적으로 감사 정보를 보존/분석할 수 있어 감사 연속성을 확보
