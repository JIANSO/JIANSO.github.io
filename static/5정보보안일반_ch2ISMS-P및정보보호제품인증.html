Q13회14회20회

다음은 접근통제 모델에 대한 설명이다. 괄호 (　)에 들어갈 용어를 기술하시오.

  • ( ① ) 모델은 주체와 객체의 등급을 비교하여 접근 권한을 부여하는 방식으로 관리자만이 정보자원의 분류를 설정하고 변경하는 방법이다.
  • 일반적으로 ACL을 사용하는 ( ② ) 모델은 주체의 신분에 근거하여 접근통제를 적용한다.
  • ( ③ ) 모델은 ( ① ) 모델과 ( ② ) 모델의 단점을 보완한 접근통제 모델로서, 역할에 기반을 두고 접근을 통제하는 모델이다.
답과 해설 보기

답: ① MAC　② DAC　③ RBAC

  • 접근통제 정책(기술)의 유형
    • 강제적 접근통제(MAC) — 객체에 포함된 정보의 허용 등급과 접근 정보에 대하여 주체가 갖는 접근 허가 권한에 근거하여 객체에 대한 접근을 제한하는 방법
    • 임의적 접근통제(DAC) — 주체나 그룹의 신분(신원, 아이디(ID))에 근거하여 객체에 대한 접근을 제한하는 방법
    • 역할 기반 접근통제(RBAC) — 중앙 관리자가 사용자와 시스템의 상호관계를 통제하며 주체의 역할(Role)에 기초하여 자원에 대한 접근을 제한하는 방법 / 강제적 접근통제(MAC)와 임의적 접근통제(DAC)의 단점을 보완한 통제 방법

  • ( ① ) : 사용자나 사용자 그룹에 근거한 사용자 중심의 접근 제어 수행
  • ( ② ) : 모든 객체는 정보의 비밀 수준에 근거하여 보안 레벨이 주어지고 허가된 사용자만 접근 가능토록 제어
  • ( ③ ) : 사용자와 객체 상호관계를 역할에 따라 접근 제어 수행

  • (1) 미 국방성 지원 보안 모델로 보안 요소 중 기밀성을 강조하며 접근을 통제하는 모델을 쓰고, 해당 모델의 No Read Up, No Write Down 속성에 대해서 서술하시오.
  • (2) 비바(Biba) 모델의 Write 속성명과 해당 속성에 대해서 서술하시오.
모범 답안과 해설 보기
모범 답안

(1) ① 벨-라파듈라 모델(BLP; Bell-LaPadula Policy)
② 보안 수준이 낮은 주체는 보안 수준이 높은 객체를 읽어서는 안 됨
③ 보안 수준이 높은 주체는 보안 수준이 낮은 객체에 기록하면 안 됨

(2) ① No Write Up
② 낮은 등급의 주체는 높은 등급의 객체를 수정할 수 없음

해설
  • 벨-라파듈라 모델은 미 국방성 지원 보안 모델로 보안 요소 중 기밀성을 강조하며 접근을 통제하는 모델
    • No Read Up — 보안 수준이 낮은 주체는 보안 수준이 높은 객체를 읽어서는 안 됨 / 상위 레벨 문서 읽기 금지, 하위 레벨 문서 읽기 허용
    • No Write Down — 보안 수준이 높은 주체는 보안 수준이 낮은 객체에 기록하면 안 됨 / 하위 레벨 문서 쓰기 금지, 상위 레벨 문서 쓰기 허용
  • 비바 모델은 벨-라파듈라 모델의 단점을 보완한 무결성을 보장하는 최초의 상업용 모델
    • No Read Down — 높은 등급의 주체는 낮은 등급의 객체를 읽을 수 없음 / 하위 레벨 문서 읽기 금지, 상위 레벨 문서 읽기 허용
    • No Write Up — 낮은 등급의 주체는 높은 등급의 객체를 수정할 수 없음 / 상위 레벨 문서 쓰기 금지, 하위 레벨 문서 쓰기 허용

전자서명

기출 1
핵심 용어
인증서 고정(Certificate Pinning)
기출문제단답·서술 구분 없음 · 직접 써 보고 답과 비교
Q129회

모바일을 이용해서 통신 시에 안전한 보안을 구성하기 위한 모바일 인증서 고정(Certificate Pinning)에 대하여 답하시오.

  • (1) 인증서 고정은 무엇인지 쓰시오.
  • (2) 인증서 고정은 어떠한 취약점을 막아주는지 쓰시오.
  • (3) 인증서 고정 요소 3가지를 쓰시오.
  • (4) 인증서 고정을 우회하는 방안 2가지를 쓰시오.
답과 해설 보기
답

(1) 사전에 정해둔 특정 인증서 또는 공개키만을 유효한 것으로 인정하도록 강제하는 보안 기법

(2) 중간자(Man-in-the-Middle; MITM) 공격

(3) ① 고정할 인증서(또는 공개키)　② 인증서 관리(보관, 갱신, 검증)　③ 오동작 및 로그 관리

(4) ① Frida 등 후킹 도구 활용해 검증 우회　② 앱을 수정하여 검증 로직 우회

해설
  • 인증서 고정은 클라이언트(모바일 앱 등)가 서버에 접속할 때 사전에 정해둔 특정 인증서 또는 공개키만을 유효한 것으로 인정하도록 강제하는 보안 기법으로, 중간자 공격 및 잘못된 인증서 체인 사용 취약점을 막을 수 있음
  • 인증서 고정 요소
    • 고정할 인증서(또는 공개키) — 앱에 하드 코딩되거나 내부 리소스에 포함되어 특정 서버의 인증서(또는 공개키)를 지정
    • 인증서 관리(보관, 갱신, 검증) — 인증서의 보관 방식, 배포 프로세스, 키 교체 방안 및 SSL/TLS의 Handshake 과정에서의 인증서 일치 여부를 검증
    • 오동작 및 로그 관리 — 인증서 불일치시 차단/알람 등 오동작 시 처리 로직 설정, 발생한 이벤트에 대한 로그를 관리
  • 인증서 고정을 우회하는 방안
    • Frida 등 후킹 도구 활용해 검증 우회 — 후킹 도구를 활용하여 HostNameVerifier 등을 후킹하여 인증서 검증 로직을 우회
    • 앱을 수정하여 검증 로직 우회 — 리버스 엔지니어링을 통해 앱을 디컴파일 후 수정하여 재배포하여 검증 로직을 우회
    • 기기에 신뢰할 수 있는 중간 CA 설치 — 기기에서 신뢰할 수 있는 CA를 설치하여 공격자가 이를 활용해 MITM 형태의 중간자 공격
