사내 보안 담당자는 예산 절감을 위해 과거에 사용하던 구형 VPN 장비를 재사용하여 IPSec 기반 VPN 환경을 구축하였다. 장비 배치 이후 네트워크 환경과 증상은 다음과 같다. 다음 내용을 바탕으로 질문에 답하시오.

사내 네트워크는 NAT(Network Address Translation)를 사용하는 사설 IP 기반 환경이다. IPSec 연결 시 ESP 프로토콜을 사용하면 정상적으로 통신이 이루어진다.
반면, AH 프로토콜을 사용할 경우 IPSec 연결 과정에서 오류가 발생하여 통신이 불가능하다. 그래서 VPN 장비의 IPSec 모듈을 최신 버전으로 업그레이드한 후에는 모든 문제가 해결되었다.
  • ① 해당 상황에서 AH 프로토콜 사용 시 연결 오류가 발생하는 근본적인 원인은 무엇인지 서술하시오.
  • ② 해당 VPN 환경에서 Pre-Shared Key(사전 공유키) 방식을 사용하여 장비 간 인증을 수행할 때의 장점과 단점을 각각 서술하시오.

모범 답안

① AH 프로토콜은 무결성 검증(ICV) 시 IP 주소를 포함한 패킷 헤더 전체를 계산 범위에 포함하지만, NAT 환경을 통과하면 IP 주소가 변조되는데, 구형 장비는 이를 정상적인 변경으로 인식하지 못한다. 결과적으로 수신 측은 계산값 불일치를 근거로 패킷이 변조되었다고 판단하여 연결을 차단하게 된다.

② Pre-Shared Key(PSK) 방식은 설정이 간편하고 신속하다는 장점이 있으나, 관리 대상이 늘어날수록 키 관리의 복잡성과 관리자의 부주의나 해킹으로 인해 키 파일이 유출될 경우, 해당 키를 사용하는 모든 통신 세션이 위험에 처하는 단점이 있다.

AH 오류 발생 과정
  1. 송신 측 VPN 장비는 변경 전 IP 헤더 정보를 포함하여 ICV를 계산
  2. 패킷이 NAT 장비를 통과하면서 IP 헤더의 주소 값이 변경
  3. 수신 측 VPN 장비는 변경된 IP 헤더 정보를 기준으로 ICV를 다시 계산
  4. 송신 측과 수신 측의 ICV 값이 일치하지 않아, 수신 측은 이를 패킷 변조로 판단하고 인증을 실패 처리
  • ESP 프로토콜은 무결성 검사(ICV 계산) 시, IP 헤더를 포함하지 않고 계산하므로 AH 프로토콜과 같은 오류는 발생하지 않음
사전 공유키 방식 장단점
  • 장점 — 설정이 간단하여 신속하게 적용할 수 있음
  • 단점
    • 관리 대상이 증가할수록 키 관리의 복잡성이 커짐
    • 관리자의 부주의 또는 해킹으로 키 파일이 유출될 경우, 해당 키를 사용하는 모든 통신 세션이 동시에 위협받을 수 있음
